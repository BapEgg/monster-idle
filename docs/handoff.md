## 2. 세계관과 시나리오

고대 문명이 생명의 숨을 연료로 태워 지구를 말렸고, 그 끝에 태어난 두 결정을 가두려 세운 8개 섬의 봉인이 한계에 이른 현재가 무대다. (확정, 이름은 가제)

**핵심 용어**

| 용어 | 정의 |
| --- | --- |
| 생명의 숨 | 생명을 자라게 하는 보이지 않는 힘(마나와 유사). 생명은 필요한 만큼만 되돌리고, 잉여 숨은 숨의 샘에만 모인다 |
| 숨의 샘 | 숨이 대량으로 솟는 곳. 마지막 8곳이 8개 섬 |
| 코어 | 숨에 새겨진 기억과 형상의 결정. 헨치의 본체 |
| 믹스 | 두 코어의 기억을 이어 새 몸으로 되돌리는 기술 (순환). 숨을 연료로 태우는 것은 기억까지 소멸 |
| 믹스할 수 있는 사람 | 균열 통과 때 몸속 숨의 흐름이 재구성된 각성자. 유전되지 않음 |
| 결계 / 봉인 / 균열 | 결계 = 섬을 숨기는 바깥 벽(빛·전파 왜곡, 들어오기만 가능) / 봉인 = 검은 결정을 가둔 안쪽 구조(왕 8명 + 봉인 기둥) / 균열 = 결계의 손상 |

**흐름**

1. **고대 황금기:** 숨이 모든 연료를 대체, 작물은 하루 만에, 대륙 이동도 하루 만에. 남용으로 고갈.
2. **전쟁과 숨 조약:** 숨 무기는 땅을 영원히 죽여 조약으로 금지. 빈틈을 노려 "살아 있는 병기"를 믹스로 만듦.
3. **두 결정:** 검은 결정 = 마족 최강 코어 + 백성을 위해 스스로를 바친 왕의 코어. 숨을 독점·배급해 인간을 "지키는" 존재(자유 없음). 흰 결정 = 용족 최강 코어 + 성자의 코어. 섞인 생명을 모두 지워 평화를 만들려 하고, 끝나면 자신도 사라져야 한다고 믿음.
4. **급한 봉인:** 연구자들이 남은 8개 샘을 결계로 숨기고, 섬의 왕 8명을 봉인에 묶음. 왕들이 수천 년 대가를 떠안음. 연구소장은 동면하며 살아남은 마지막 연구자.
5. **현재:** 봉인 한계 → 검은 결정의 영향으로 헨치 폭주 → 사냥 = 폭주한 헨치의 코어가 봉인 아래로 빨려가기 전에 회수하는 구조. 지구의 숨이 균열을 통해 새어 나감.
6. **주인공:** 균열에 휘말린 현대 지구인 5명이 각성해 연구소에 순차 합류.
7. **1부:** 왕 해방 → 2\~3번째 섬에서 봉인 기둥이 꺼지는 징후 → 중반에 "왕을 구할수록 봉인이 약해진다"와 소장의 비밀 공개 → 목표 전환 "왕을 희생시키지 않는 새 봉인" → 1부 결말.
8. **2부:** 지구로 확장 (미정).

**주제:** 생명을 희생시켜 유지되는 평화를, 생명을 되살리는 믹스로 바꿀 수 있는가. 검은 결정은 빼앗아 지키고, 흰 결정은 지워서 지키며, 주인공은 함께 사는 세 번째 길을 찾는다.

**서술 방식:** 대사는 튜토리얼과 핵심 장면만. 고대사는 연구 노트·도감, 현재 사건(재회·봉인 기둥 등)은 플레이 중 바로 연출.

**프롤로그 (초안):** 균열에 휘말림 → 첫 헨치가 막아서다 쓰러짐 → 검은 결정의 그림자가 주인공을 보고 멈칫 → 연구소장 구출 → 쓰러진 헨치 코어로 첫 믹스.

## 4. 헨치 시스템 규칙

헨치는 레벨이 아니라 역할·스탯·시너지 때문에 바뀌어야 하며, 초반 헨치도 끝까지 쓸 수 있게 설계한다.

| 항목 | 규칙 | 상태 |

| 종족 | 용(동경) · 마(두려움) · 야수 · 식물 · 기계(도구) · 정령(믿음) · 곤충 · 비행 | 확정 |
| MVP 수량 | 종족당 8종(하급 4 · 중급 2 · 상급 1 · 왕 1) × 8 = 64종 + 길잡이 8 | 확정 |
| 역할 | 종 단위 탱커 · 힐러 · 근접딜러 · 원거리딜러. 모든 종족에 4역할 존재 | 확정 |
| 레벨 | 헨치 레벨 상한 = 플레이어 레벨 | 확정 |
| 등급 보정 | 등급당 능력치 약 +10% (희귀함 위주, 압도적 차이 없음) | 초안 |

| 출현 | 하급 = 고향 섬 입문 + 다른 섬 입문 1곳, 중급 = 특수 지역, 상급 = 심장부 희귀, 왕 = 섬의 왕 보스 | 초안 |

## 8. 밸런싱 · 확률

확률은 "하루 목표 획득량"을 먼저 정하고 거꾸로 계산하며, 실제 값은 프로토타입에서 하루 처치 수를 측정한 뒤 확정한다.

| 항목 | 목표 | 상태 |
| --- | --- | --- |
| 일반 코어 | 하루 10\~15개 | 확정 |
| 빛나는 코어 (좋은 접미사 확률↑) | 주 3개 | 확정 |
| 변이체 | 월 3\~4마리 | 확정 |
| 도감 64종 | 1\~2달에 완성, 하루 새 종 1\~2마리 | 확정 |
| 섬의 왕 | 하루 2회(클리어 시만 차감), 처치당 조각 2\~3, 조각 25 = 왕 코어(주 1\~2개), 낮은 확률 즉시 드랍, 연습 모드(보상 없음), 클리어 단계 소탕 | 확정 |
| 레벨 | MVP 최고 60, 약 1개월 (첫날 15 · 1주 30 · 2주 40 · 3주 50 · 4주 60) | 확정 · 곡선은 초안 |
| 드랍률 | 드랍률 = 하루 목표 ÷ 하루 처치 수 (예: 하루 1,000마리면 1\~1.5%) | 공식 확정 |
| 확률 보너스 공식 | 모든 보너스를 먼저 더함(B) → 수확 체감: 유효 보너스 = B × K ÷ (B + K) → 최종 = 기본 확률 × (1 + 유효 보너스). 변이체 K = 50% | 확정 |
| 영구 변이 보너스 | 유료가 아닌 변이 도감 달성 보상 | 확정 |
| 확률 공개 | 유료로 얻는 확률형 아이템은 확률 공개 (게임산업법) | 확정 |

- 광고: 선택형 보상 광고만 (방치 보상 2배 등), 강제 광고 없음, 광고 제거 패키지
- 마크(소모품, 뽑기): 드랍률·경험치·변이 조우율 소폭 상승, 위 수확 체감 공식 적용

- 팔지 않는 것: 변이체, 섬의 왕 코어, 비밀 레시피, 믹스 전용 상위 헨치
- 헨치 스탯 강화 아이템(포켓몬 능력치 아이템 같은 것)은 게임이 잘되면 추후 검토

## 10. 개발 인계 (Claude Code용)

Claude Code는 이 섹션을 작업 규칙으로 삼고, 기능 하나를 끝낼 때마다 멈춰서 사용자가 Godot에서 직접 확인하게 한다.

**환경**

| 항목 | 값 |
| --- | --- |
| 프로젝트 경로 | `C:\dev\monster-idle` |
| 엔진 | Godot 4.x 표준(GDScript), 렌더러 호환성(Compatibility) |
| Godot 실행 파일 | 일반 버전은 사용자가 편집용, 콘솔 버전(`..._win64_console.exe`)은 Claude Code가 명령 실행·로그 확인용 (경로는 사용자가 알려줌) |
| 화면 | 가로, 2D 쿼터뷰, 휴대폰 비율 차이는 가운데 전투 영역이 늘어나는 구조, 노치를 고려해 조작 버튼은 가장자리보다 안쪽 |
| 기획 문서 | `docs/handoff.md` (이 문서를 내보낸 것) |
| 버전 관리 | Git, 기능 단위로 커밋 |

**작업 규칙**

1. 기능 하나씩 만든다. 끝나면 무엇을 확인하면 되는지(F5 전체 실행 / F6 현재 장면 실행, 조작 방법)를 짧게 알려주고 멈춘다.
2. 그림은 처음엔 도형·색으로 대체한다 (헨치는 색 원 + 이름표, 선공은 빨간 이름표).
3. 수치(속도, 확률, 레벨)는 한곳의 설정 파일에 모아 바꾸기 쉽게 한다.
4. 헨치 데이터(64종)는 코드에 박지 않고 데이터 파일(JSON 또는 Godot 리소스)로 분리한다.
5. 원작 고유 용어(코어·헨치·믹스)는 나중에 바꿀 수 있게 화면 문구를 한곳에서 관리한다.
6. 기획과 다르게 만들어야 할 이유가 생기면 바꾸기 전에 사용자에게 묻는다.
